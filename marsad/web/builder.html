Locks comparability

Change any of these and this run can only be compared with other runs that share the same values. marsad compare refuses to treat them as equivalent.

Crop and FIR are 0.25 and 9 by station convention. Every archived survey uses them; changing either orphans this run.

rtl_power_fftw has no crop of its own: the recorder asks for an overlap of 100 × crop between hops and the analyser drops that share from each hop's edges, so the kept parts still tile. Its dB are a power spectral density on its own scale, about 26 dB below rtl_power's 50 kHz scale at 2.4 MS/s (measured 2026-10-22); a run from one engine is never comparable with the other, and the fingerprint says which engine it was.

Run settings

Free to change

None of these alter the frequency grid or the measured levels, so a run is still comparable across different durations, tags and analysis options.

Duration and sweeps are the same knob — sweeps = duration ÷ integration, exactly. Set whichever you think in; the other follows. Sweeps is usually the one that matters, because it is what occupancy resolution and the floor percentile depend on.

Device follows the receiver, using the index recorded in station.json. That order is not guaranteed across replugs, so run rtl_test and read its device list before a long run. Override the number here if the order has changed.
